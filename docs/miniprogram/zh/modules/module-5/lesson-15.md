# 第 15 课：审核策略与常见驳回处理

## 15.1 审核前自查清单

| 检查项 | 说明 |
|--------|------|
| 功能完整性 | 所有按钮可点，无 TODO 占位 |
| 测试账号 | 涉及登录的页面提供测试账号（填在审核备注里） |
| 隐私协议 | 收集手机号/位置需声明隐私协议并勾选同意 |
| 类目匹配 | 提交时选择与实际功能匹配的类目，不要图省事选"工具" |
| 截图 | 提供 5-10 张功能截图，覆盖主要页面 |

## 15.2 常见驳回原因与对策

| 驳回原因 | 频率 | 对策 |
|----------|------|------|
| "功能不完整" | 高 | 确保所有路径可走通，不留死胡同 |
| "类目不符" | 高 | 重新选类目，功能描述与实际一致 |
| "隐私协议" | 中 | 加 `wx.getPrivacySetting` 检查 + 隐私弹窗 |
| "诱导分享" | 中 | 去掉"转发到朋友圈才能继续"等文案 |
| "测试账号无法登录" | 中 | 审核备注中提供可登录的测试账号 |
| "内容涉及敏感词" | 低 | 替换文案，避免政治/医疗/金融未授权内容 |

## 15.3 隐私协议（2023 年强制）

涉及获取手机号、位置、相机等权限，必须先展示隐私协议：

```xml
<!-- 页面中 -->
<button wx:if="{{!privacyAgreed}}" open-type="agreePrivacyAuthorization"
        bindagreeprivacyauthorization="onAgreePrivacy">
  同意隐私协议
</button>
```

```js
onAgreePrivacy(e) {
  if (e.detail.agree) {
    this.setData({ privacyAgreed: true })
    // 再触发实际权限请求
  }
}
```

> 不展示隐私协议，涉及隐私 API 的小程序一律驳回。

## 15.4 类目选择技巧

| 产品类型 | 推荐类目 | 备注 |
|----------|---------|------|
| 天气/工具 | 工具 > 信息查询 | 个人主体可选 |
| 家谱/社区 | 社交 > 社区/论坛 | 需企业主体 |
| 预约/咨询 | 生活服务 > 预约 | 需企业主体 |
| 电商 | 电子商务 > 网上商店 | 需企业 + 支付 |
| 教育 | 教育 > 在线教育 | 需办学许可证（慎选） |

> 类目错了是高频驳回原因。不确定时选最接近的，而非"最大"的。

## 15.5 审核周期

- 普通提交：1-3 个工作日
- 加急（有配额）：24 小时内
- 被驳回后重新提交：重走完整审核，不加快

---

**小结**：审核最贵的不是费用，是时间。提交前自查清单能减少 80% 的驳回。类目 + 隐私协议是两大高频死因。
