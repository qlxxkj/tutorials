# 第 11 课：与 AI 合作的最佳实践

> 📌 **学习目标**：学会和 Claude Code 高效协作，避免常见坑
> ⏱️ **预计时长**：20 分钟
> 🎯 **本节节奏**：原则 → 技巧 → 避坑

---

## 一、和 AI 合作的 5 个核心原则

### 原则 1：像在团队里带人一样

把 Claude 当成你的新同事：
- 交代清楚任务目标
- 给足背景信息
- 及时给出反馈
- 认可好的结果

**差的做法：**
```
帮我弄一下
```

**好的做法：**
```
我有一个销售数据文件，
需要你帮我统计各产品的销售额，
格式要求是...
```

### 原则 2：一次只说一件事

❌ 混乱的指令：
```
帮我写个脚本，还要整理文件夹，还要生成报告
```

✅ 清晰的指令：
```
先帮我写一个数据处理的脚本
（完成后再说下一个任务）
```

### 原则 3：给出上下文

 Claude 不知道你的业务背景，你需要主动告诉它：
```
我们是做电商的，
这个销售数据包含：订单号、商品名、数量、金额、客户地区
```

### 原则 4：及时反馈

 Claude 做完后，检查结果：
- 正确 → 告诉它"很好，保持这个风格"
- 不对 → 具体告诉它哪里不对
- 不完整 → 告诉它还需要补充什么

### 原则 5：迭代优化

不要期望一次就完美：
```
第一版：生成基础脚本
第二版：加上错误处理
第三版：优化性能
第四版：加上日志
```

## 二、高效对话的技巧

### 技巧 1：使用结构化指令

```
【任务】读取 E:/data/sales.csv
【要求】
- 按产品分组统计销售额
- 按销售额降序排列
- 输出为 Markdown 表格
【输出】保存到 E:/output/report.md
```

### 技巧 2：分段描述

复杂任务分段说：
```
第一步：帮我读取这个数据文件
（等待 Claude 完成）
第二步：现在帮我统计每个产品的销售额
（等待 Claude 完成）
第三步：生成报告并保存
```

### 技巧 3：提供示例

```
输出格式参考这个：
| 产品 | 销售额 | 占比 |
|------|--------|------|
| A    | ¥5000  | 50%  |
| B    | ¥3000  | 30%  |
```

### 技巧 4：善用追问

```
这个结果对吗？帮我验证一下
```
```
能不能优化一下，让运行速度更快？
```
```
有没有更好的方式来实现这个功能？
```

## 三、常见错误和避坑

### 错误 1：指令太模糊

❌ "帮我写个东西"
✅ "帮我写一个 Python 脚本，功能是..."

### 错误 2：期望太高

❌ "帮我做一个完整的电商网站"
✅ "先帮我做一个商品列表页面"

### 错误 3：不检查输出

 Claude 可能会犯错，养成检查的习惯：
```
请执行前，先列出你要做的步骤
```
```
执行后，让我确认一下结果
```

### 错误 4：一次性说太多

如果任务很复杂，拆分：
```
先做第一步...
（确认完成后）
现在做第二步...
```

### 错误 5：忽略安全性

对于删除、修改重要文件的操作：
```
在执行删除前，先让我确认一下
```
```
请先列出要删除的文件，我确认后再执行
```

---

## 四、安全检查清单

在执行重要操作前，让 Claude 先给你看计划：

```
在开始执行前，请先列出你要做的所有步骤，
等我确认后再开始
```

或者：
```
请先只做模拟，不要实际修改任何文件，
让我看看你打算怎么做
```

## 五、本节小结

| 原则 | 说明 |
|------|------|
| 当同事 | 交代清楚、给足背景、及时反馈 |
| 一次一事 | 不要一次说太多任务 |
| 给上下文 | 主动告诉 AI 业务背景 |
| 迭代优化 | 不满意就继续说 |
| 安全检查 | 重要操作前先确认 |
